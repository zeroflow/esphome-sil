## Phase Goal

ROADMAP Goal (not in user-story form; MVP framing needs `/gsd mvp-phase 1` — surfaced for morning review, no story invented): Developer runs `sil up` and real ESPHome firmware, built in the pinned image and running directly on the host, drives simulated fans whose RPM flows back over the sim-bus; the loop is observable via `sil status`, survives restarts of either side, and stops cleanly with `sil down`.

This plan starts the **Walking Skeleton** (see `SKELETON.md`). The skeleton is a three-plan tracer chain because one plan cannot carry its ~30 files under the 15-file budget: 01-01 proves the firmware seam (pinned-image build -> static program on the host -> sim-bus), 01-02 closes the loop through the Go simulator, 01-03 puts `sil up/status/down` in front of it. Each link leads with a tracer task with its own end-to-end check.

<objective>
Prove the riskiest external seam on real firmware: the repo's sim_bus component and Phase 1 example build in the pinned ESPHome image as a static host program, the program runs on the host against a Unix socket chosen at runtime, and fan duty and RPM cross that socket in both directions while the encrypted native API drives the fans.

Purpose: everything later (engine, supervisor, CLI) stands on this seam; a wrong assumption here (image, static link, SIL_BUS override, channel names, encryption) is caught after one plan instead of after the whole skeleton.
Output: Go module and Makefile, internal/apperr, internal/clock (Real), internal/fwbuild, components/sim_bus (moved from prototype/), examples/fan-skeleton.yaml, firmware-level e2e harness, TestFirmwareBus, e2e/api_client.py.
</objective>
