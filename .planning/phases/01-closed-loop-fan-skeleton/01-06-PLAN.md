## Phase Goal

ROADMAP Goal (not in user-story form; see 01-01-PLAN.md note). This plan pins the sim-bus wire format so both sides of the loop agree byte for byte where it matters (criterion 3: "the wire format passes the same golden vectors in both the Go and the C++ tests").

<objective>
Freeze the sim-bus wire grammar and session messages in protocol/PROTOCOL.md, pin them with one golden-vector file, and implement a strict codec on both sides: Go (internal/bus/codec.go, same public API as 01-02) and a header-only C++ codec (components/sim_bus/sim_protocol.h) that the firmware hub adopts in plan 01-10.

Purpose: BUS-04 and BUS-01; removes the risk that a hand-rolled parser drifts between the two languages (RESEARCH Pitfall 9, float formatting differences).
Output: PROTOCOL.md, frames.tsv, strict Go codec + test, C++ header + test, Makefile targets test-cpp and test-cpp-image.
</objective>

C++ (components/sim_bus/sim_protocol.h), namespace esphome::sim_bus::proto, no ESPHome includes:
  constexpr int PROTO = 1; constexpr size_t MAX_LINE = 4096;
  struct Field { std::string key; bool is_str; std::string text; };   // text = decoded string or raw number literal
  struct Frame { std::vector<Field> fields; const Field *find(const std::string &key) const; std::string kind() const;
                 Frame &str(const std::string &k, const std::string &v); Frame &num(const std::string &k, float v); Frame &i64(const std::string &k, int64_t v);
                 bool get_str(const std::string &k, std::string &out) const; bool get_num(const std::string &k, float &out) const; bool get_int(const std::string &k, int64_t &out) const; };
  enum class Err { NONE, EMPTY, TOO_LONG, NOT_OBJECT, NESTED, BAD_KEY, BAD_VALUE, BAD_ESCAPE, BAD_CHAR, DUP_KEY, MISSING_K, BAD_K, BAD_NUMBER, TRAILING };
  inline const char *err_name(Err e);   // lowercase class names identical to the Go DecodeError.Class values
  inline Err parse(const std::string &line, Frame &out);   // line without newline
  inline std::string encode(const Frame &f);               // incl. newline; num() refuses non-finite values

Vector file format (protocol/vectors/frames.tsv), one row per line, tab separated, lines starting with # are comments:
  name <TAB> valid   <TAB> line <TAB> tuple      e.g. out_basic  valid  {"k":"out","ch":"port1.duty","v":0.4,"t":1000}  k=s:out;ch=s:port1.duty;v=n:0.4;t=i:1000
  name <TAB> invalid <TAB> line <TAB> class      e.g. dup_key    invalid {"k":"out","k":"in"}  dup_key
  name <TAB> encode  <TAB> line <TAB> tuple      encoders must produce `line` byte for byte from `tuple`
  tuple: fields in line order, `;` separated, `key=s:<string>` | `key=n:<float32 literal>` | `key=i:<int64>`; test strings never contain `;` or tabs
