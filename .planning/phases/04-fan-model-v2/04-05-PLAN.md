## Phase Goal

ROADMAP Goal (not in user-story form; surfaced for review, no story invented per the MVP rules): see 04-01-PLAN.md. This plan delivers the seed half of criterion 3 ("two runs with the same seed and duty sequence give identical traces"): the user chooses the noise seed of an instance, sees it, and gets it back after every restart (D-15).

<objective>
Put the noise seed under the user's control end to end. `sil up --seed N` reaches every plant of the instance through spec.json and the supervisor's engine config, `sil status` shows it as `sim.seed`, run.json records it, and it survives `sil sim restart` and `sil fw restart`. Without the flag the seed is a fixed default, so every run repeats. An out-of-range seed is refused before anything is written.

Purpose: MODEL-10 (D-15). Split out of 04-04 at plan revision (the checker found 04-04 at 16 files, and its seed task shared no file with the tach tasks).
Output: the `--seed` flag, UpOptions/Spec/RunFile/SimStatus fields, the supervisor wiring, unit tests in cli, lifecycle and supervisor, and an e2e test of the whole path.
</objective>

- **Origin:** this is the former Task 3 of 04-04, split out at plan revision (2026-11-10) to keep both plans under 15 files. It is restructured tracer-first: Task 1 carries the seed from the flag to status, and Task 2 adds the range check, run.json and the restart guarantees.
- **Wave 3, parallel with 04-04:** the two plans share no file. 04-04 owns internal/model and internal/engine and the lint. This plan owns cli, lifecycle, instance, supervisor, control and e2e/seed_test.go. The default seed therefore lives in lifecycle (`lifecycle.DefaultSeed`), not in internal/model. The seed reaches the plants through engine.Config.Seed, which 04-01 declared and passes to every model.NewPlant.
- **Depends on 04-03:** both edit internal/cli/cli.go, internal/supervisor/supervisor.go and internal/control/control.go.
- **Seed storage (Assumption A-SEED, flagged):** spec.json carries the seed (written by lifecycle.Up, read by the supervisor). The supervisor copies it into run.json and status `sim.seed`. 0 is a valid seed, and nil (no flag) means lifecycle.DefaultSeed. The range is capped at 2^53-1 with the `invalid_argument` code, which is already in the `apperr.Registry` map (a package variable in internal/apperr/codes.go, checked against every apperr.Failed/Infra call site by TestRegistryMatchesCallSites), so no new code is needed.
- **No fan dependency:** the e2e test only reads the seed. It runs on whatever library newEnv gives (the shipped files are still schema 1 at this wave, and 04-08 later pins newEnv to the v0.1.0 fixtures), and it asserts nothing about fans.
- **Wall-clock lint covers tests:** use the Manual clock in supervisor tests and env.WaitStatus/Sil in e2e. No time.Sleep or time.Now.
- **Pattern analogs:** 04-PATTERNS.md section "cli.go" (UpCmd kong tags, the Fan flag as the model for Seed); "internal/instance/instance.go (MOD: Spec.Seed)" in the File Classification table (existing Spec fields); "control.go, supervisor.go" (SimStatus, status mapping). lifecycle.go has no PATTERNS row: its analog is its own pure pre-write checks checkWebOptions/resolveFan (see "Plan file-name mapping"). Tests: cli_test.go → TestUpFanFlagReachesUpOptions; lifecycle_test.go → TestCheckWebOptions; supervisor_test.go → fanSupervisor and the SimRestart tests of policy_test.go; e2e/seed_test.go → e2e/restart_test.go (rsInstance.restart) and TestFanTomlUnknownKey (refused before any build).
