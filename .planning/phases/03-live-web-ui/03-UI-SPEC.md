| Property | Value |

## Visual Language (locked: D-01..D-06)

- Character: classic HP/Keysight bench oscilloscope front panel (InfiniiVision-style). Restraint over glow. Dark grey bezel, black screens with a faint graticule, grey softkey buttons, crisp sans labels with tabular numerals. Explicitly not neon or cyberpunk.
- The **only** light effect on the page is the soft glow around lit virtual LEDs. No glow, shadow or blur on traces, text, buttons or panels. No gradients except the subtle LED lens highlight.
- Corners: `border-radius: 2px` on screens, inputs, softkeys and panels. LED lenses are circles. No pill shapes, no large radii.
- Style reference only: no vendor name, logo or trademark text anywhere on the page. Page title is `sil — {instance name}`; header brand text is the instance name only.
- Page identity: `<link rel="icon" href="data:,">` so there is no failed favicon request and no external reference.

## Layout Contract (D-05, D-06)

**Primary visual anchor:** the 2x2 block of scope screens with their RPM readouts (Display 28px, channel color). They are the largest, highest-contrast area and the first read; the header and bottom strip are chrome around them.

Page = header bar, a grid of port panels, a bottom strip. One screen, no vertical scroll at a **1280 x 720 viewport and up**. Between 1024 and 1279 px wide the same 2x2 layout is used and vertical scroll is allowed.

```
+------------------------------------------------------------------------------------+
| HEADER 64: instance | SIM TIME | TIME FACTOR | FIRMWARE | REAL TIME | message line | LINK |
+---------------------------------------+--------------------------------------------+
| PORT 1 panel (yellow)                 | PORT 2 panel (green)                       |
| [P1][fan select    ][ RPM ][ DUTY ]   | [P2][fan select    ][ RPM ][ DUTY ]        |
| scope screen (uPlot)                  | scope screen                               |
+---------------------------------------+--------------------------------------------+
| PORT 3 panel (blue)                   | PORT 4 panel (pink)                        |
+---------------------------------------+--------------------------------------------+
| BOTTOM STRIP 128:  LEDS (flex 1)  |  USR1 USR2 USR3  |  TEMPERATURE  HUMIDITY  APPLY VALUES |
+------------------------------------------------------------------------------------+
```

| Breakpoint | Behaviour |
|------------|-----------|
| >= 1024 px | Port panels in a 2x2 grid (ports 1,2 top row; 3,4 bottom row), always 2x2, never 4x1. Header is one row. Bottom strip is three groups side by side. |
| < 1024 px | One column, page scrolls vertically. Header wraps to two rows (run-info fields on row 1, message line and LINK on row 2). Bottom strip groups stack: LEDs, USR, environment. |
| < 640 px | Each panel's top row splits: row 1 = port chip + fan select (select takes the rest), row 2 = RPM and DUTY readouts. LED lenses wrap onto a second line if they do not fit. |

Vertical budget at 1280 x 720: header 64 (includes its own padding) + page padding and gaps 32 (8 top + 8 header-to-grid + 8 grid-to-strip + 8 bottom) + bottom strip 128 = 224, so the grid gets 496. Two panel rows with an 8px gap give 244 per panel; minus 16 panel padding, the 44px top row and an 8px gap, the scope screen gets 176. The scope screen height is `flex: 1` inside the panel and never shrinks below 128.

Bottom strip fit check (128 = 8 top padding + 112 content + 8 bottom padding). The tallest group is LEDS: label 18 + 4 gap + well (8 padding top and bottom = 16) + lens 24 + 4 + caption 18 + 4 + hex 18 (68) = 106, which fits in 112 with 6 to spare. USR group: label 18 + 4 + cap 48 = 70. Environment group: label 18 + 4 + field label 18 + input 44 = 84. LED captions are therefore capped at one line (see LED group).

The grid renders one panel per entry in the status `ports` array (4 for Rev 3.3), never a hard-coded 4. The LED group renders one lens per entry of `leds.strip` (5 for Rev 3.3).

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a label and its value, gap between lens and caption lines, inline padding in chips |
| sm | 8px | Page padding, grid gap, panel padding, gap between controls in a row, header cell padding |
| md | 16px | Gap between bottom-strip groups, gap between LED columns, padding inside screens |
| lg | 24px | LED lens diameter |
| xl | 32px | Vertical gap between stacked bottom-strip groups below 1024px |
| 2xl | 48px | Height of USR button caps |
| 3xl | 64px | Header bar height |

Exceptions:
- **Interactive minimum 44px** (multiple of 4, matches D-06): every button, select and input has `min-height: 44px` and `min-width: 44px` at **all** widths (one rule, no desktop/phone split). Port-panel top row and env inputs are 44px high. USR caps are 48px high (2xl).
- Bottom strip height 128px and plot minimum height 128px are layout sizes, not spacing tokens (both are multiples of 4).
- 1px and 2px borders, graticule hairlines and focus/error outlines (2px) are strokes, not spacing. The 2px focus-ring offset is an explicit exception to the 4px minimum step: it is a stroke offset that does not take layout space.

## Typography

Exactly 4 sizes and 2 weights (400 regular, 600 semibold).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 12px | 400 (600 for port chip and axis unit tags) | 1.5 | Field labels (`SIM TIME`, `FIRMWARE`), unit tags, LED segment name and `#rrggbb`, uPlot axis ticks, in-screen scale/legend text. Labels are uppercase with `letter-spacing: 0.04em`, except the LED hex code and segment names which keep their exact case. |
| Body | 14px | 400 (600 for softkey text) | 1.5 | Fan select text, softkey captions (`APPLY VALUES`, `USR1`), message line, header field values that are words (`CONNECTED`, `IN SYNC`), instance name (600) |
| Heading | 20px | 600 | 1.2 | Duty readout, sim time, temperature/humidity input values |
| Display | 28px | 600 | 1.2 | RPM readout |

Rules:
- Every number uses tabular numerals. Readout slots have a fixed width in `ch` so digits do not shift neighbours: RPM 5ch, duty 5ch (e.g. `100.0`), sim time 10ch.
- Number formats: RPM integer; duty percent with 1 decimal (`40.0`), the unit `%` as a Label tag next to it; sim time `HH:MM:SS.s` from the API's microsecond value (formatting only); time factor `x1`.
- No monospace face, no italics, no text below 12px.

## Color

Dark palette, one tuned set (D-02). Hex values are the contract; CSS custom properties are named `--bezel`, `--screen`, `--softkey`, `--text`, `--text-dim`, `--ch1..ch4`, `--warn`, `--error`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#23262a` (bezel), border `#33373c` | Page background, header bar, port panel body, bottom strip, group backgrounds |
| Secondary (30%) | `#07080a` (screen black) plus `#3a3f45` (softkey grey) | Scope screens, readout wells, LED well, message line well, input wells (screen black); buttons/selects/softkeys (softkey grey, hover `#444a51`, pressed `#2d3136`, top edge `#4d545c`, bottom edge `#1b1d20`) |
| Accent (10%) | Port channel colors: P1 `#ffd400` yellow, P2 `#2fd36b` green, P3 `#3d8bff` blue, P4 `#ff5fd2` pink | See "Accent reserved for" |
| Destructive / error | `#ff4d4d` | Error outline, message-line error text, `DISCONNECTED` states. There are no destructive actions in this phase. |
| Warning | `#ff8a1f` (orange) | "Behind real time" field only. Deliberately not amber, to keep it distinct from port 1 yellow. |
| Text | `#e6e8eb` primary, `#9aa1a9` dim | Primary: values, softkey text. Dim: labels, units, hex codes, graticule labels, disabled-looking secondary text |
| Graticule | `#20252b` major lines, `#2e343b` center lines, screen border `#3a4047` | Scope screen grid only |
| LED off | `#121416` lens, `#2a2e33` rim | Unlit virtual LED |

Accent reserved for (explicit; never "all interactive elements"):
1. Plot traces for that port (RPM solid, duty dashed).
2. The port chip (`P1`..`P4`) fill and the 2px top edge of that port's panel.
3. The RPM and duty readout numerals of that port.
4. That port's axis tick labels inside its scope screen (RPM axis full color, duty axis same color at 70% alpha) and its in-screen legend.

Nothing else on the page uses a channel color. Softkeys, header text, focus rings and the held-button state are neutral.

Semantic rules:
- Status color never relies on green: port 2 is green, so "connected" is plain primary text and "disconnected" is red text. `FIRMWARE`: `CONNECTED` primary, `DISCONNECTED` red. `REAL TIME`: `IN SYNC` primary, `BEHIND` on an orange `#ff8a1f` chip with `#07080a` text.
- Port identity is never color-only: the chip always says `P1`..`P4`, RPM is a solid 2px line and duty a dashed 1px line (`[4,4]`), and the in-screen legend spells `RPM` and `DUTY`.
- Focus ring: 2px `#e6e8eb`, 2px offset, on `:focus-visible` for every interactive element. Never removed.
- Held USR cap (server-reported): fill `#d9dde2`, text `#15171a`, no color accent.
- Error outline: `outline: 2px solid #ff4d4d` on the offending field.
- Stale (WS lost): see "Connection and Stale State".
- Contrast (checked against the surface each is drawn on): all channel colors and `#9aa1a9` >= 4.5:1 on bezel and screen; the intentionally dimmed stale state (opacity 0.4) is exempt because it conveys "not live".

LED display gamma (presentation only, D-04): the rendered lens color per channel is `round(255 * (c/255)^(1/2.2))`, so a dim strip value is visibly dim rather than black. Glow strength `L = max(r,g,b)/255` after gamma. Lit lens: `background` = rendered color, `box-shadow: 0 0 calc(4px + 12px*L) calc(2px*L) rgba(rendered color, 0.6*L)`, plus a faint 10% white highlight in the upper left. Off (`#000000`): `#121416` lens, no glow. The caption under it always shows the **raw** `#rrggbb` from the API, not the gamma-corrected value.

## Component Contract

### 1. Header bar (64px, bezel, 8px padding, fields separated by 1px `#33373c` dividers)

Fixed-width cells so nothing moves when values change or when the warning appears. Each cell: Label above (12px dim, uppercase), value below.

| Cell | Label | Value | Notes |
|------|-------|-------|-------|
| Instance | (none) | instance name, Body 600 | From status `instance`. Truncates with ellipsis. |
| Sim time | `SIM TIME` | `HH:MM:SS.s`, Heading | Always sim time from the API, never a browser clock. |
| Time factor | `TIME FACTOR` | `x1`, Body | Rendered from the API field (fixed at 1 in M1). |
| Firmware | `FIRMWARE` | `CONNECTED` / `DISCONNECTED`, Body | `DISCONNECTED` in red. Server-reported. |
| Real time | `REAL TIME` | `IN SYNC` / `BEHIND` | Cell is always present at the same width. `BEHIND` = orange chip, `aria-label="Simulator behind real time"`. The flag is computed by the engine and exposed in status; the page does no timing math. |
| Message line | (none) | see below | `flex: 1`, min-width 160px, screen-black well with 1px border, 8px padding, single line with ellipsis (two lines max below 1024px), `title` attribute carries full text. `role="status"` + `aria-live="polite"` (errors use `role="alert"`). |
| Link | `LINK` | `CONNECTING` / `LIVE` / `DISCONNECTED, RETRYING` | WS state. `DISCONNECTED, RETRYING` in red. Fixed width fits the longest string. |

### 2. Port panel (one per port)

- Panel: bezel body, 1px `#33373c` border, **2px top edge in the port's channel color**, 8px padding, 8px gap.
- Top row (44px): `[port chip] [fan select (flex 1, min 160px)] [RPM readout] [DUTY readout]`.
  - Port chip: a non-interactive tag, 40px wide by 32px high, filled with the channel color, text `#07080a` Label 600, content `P1`..`P4`. It is not interactive, so the 44px minimum does not apply.
  - Fan select: native `<select>`, softkey grey, 44px high, Body text, options are the fan-library names exactly as returned by the fan-library list operation. `aria-label="Fan on port N"`. See Interaction Contract.
  - RPM readout: value in Display (channel color), unit tag `RPM` (Label, dim) to the right on the baseline. Slot 5ch.
  - DUTY readout: value in Heading (channel color), unit tag `% DUTY` (Label, dim). Slot 5ch.
- Scope screen below the row: fills the remaining height (min 128px). See "Scope screen".

### 3. Scope screen (uPlot, one per port)

- Screen-black well, 1px `#3a4047` border, no rounded corners beyond 2px.
- **Graticule:** 10 horizontal divisions (6 s each over the 60 s window) by 4 vertical divisions, 1px `#20252b`; center horizontal and vertical lines `#2e343b`. Drawn by uPlot's grid, no images.
- **Window:** rolling 60 s of sim time, right edge = the latest sample's sim time (roll mode). The x-axis has no tick labels; a Label-size text `6 s/div` sits in the bottom-left corner inside the screen in dim text, like a scope's timebase readout.
- **Axes (fixed, D-13):** left axis = RPM, 0 to the plugged fan's `max_rpm` (4 divisions; tick labels at 0, 50 %, 100 % of max only), channel color. Right axis = duty, 0 to 100 (tick labels `0`, `50`, `100`), channel color at 70% alpha. No autoscale. A fan swap re-scales the RPM axis once.
- **Traces:** RPM = 2px solid line, linear path, channel color. Duty = 1px dashed `[4,4]` line, stepped path (`align: 1`, duty is a held value), channel color, on the right-hand scale. Missing samples (firmware disconnected) are `null`: draw a gap, never a fake zero (`spanGaps: false`).
- **Legend:** in-screen top-left, Label size, two entries `RPM` (solid sample) and `DUTY` (dashed sample) in channel color. Static, not interactive. uPlot's built-in legend and cursor are disabled (`legend.show: false`, `cursor.show: false`): the scope has no hover.
- **Empty (before first sample):** graticule drawn, no traces, and two centered lines inside the screen: a Label 600 heading in primary text and a Label body line in dim text (copy in the Copywriting Contract). The text disappears when the first sample for this port is plotted.
- **Performance contract:** uPlot instances and the `Float64Array` ring buffers live in module scope (or `Alpine.raw`), never in Alpine `x-data`. Redraw coalesced to at most 20 per second via `requestAnimationFrame`. Client ring = 60 s window + 2 s margin per series. Server history ring about 5 min, recommended 10 Hz sample rate *(default)*; the page plots server samples as received and does not resample, smooth or interpolate.

### 4. Virtual LED group (bottom strip, left, flex 1)

- Group label `LEDS` (Label, dim) above a screen-black well (8px padding).
- One column per strip entry, 16px apart: lens (24px circle, 2px rim `#2a2e33`) / segment caption (Label, primary, exact name from the HELLO manifest `segments`; if several segments cover an index, join with `, `; if none, an em dash `—`) / `#rrggbb` (Label, dim, tabular, exactly the value `sil status` reports for that index).
- Lens color, glow and off state per "LED display gamma" above. Update at the incoming rate (<= 20 Hz), painted via `requestAnimationFrame`.
- `aria-label` per lens: `{segment} {#rrggbb}`.

### 5. USR buttons (bottom strip, middle)

- Group label `BUTTONS`. Three caps `USR1`, `USR2`, `USR3`: softkey grey, 48px high, min 72px wide, 8px apart, Body 600 centered.
- Behaviour per Interaction Contract. Held state (server-reported only): inverted cap `#d9dde2` fill / `#15171a` text, 1px inset border `#8d949c` (a border, not a shadow), no transition.
- `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`, and `contextmenu` prevented on the caps so a long touch hold does not open a menu.
- `aria-pressed` mirrors the server-reported held state.

### 6. Environment inputs (bottom strip, right)

- Group label `ENVIRONMENT`. Two fields side by side plus one softkey, 8px apart:
  - `TEMPERATURE` (Label above) + text input (44px high, screen-black well, 1px `#4d545c` border, Heading text right-aligned, 96px min width) + unit tag `°C` (Label, dim).
  - `HUMIDITY` + input + unit tag `%RH`.
  - `APPLY VALUES` softkey (44px high, min 72px wide, grows to fit its caption).
- Inputs are `type="text" inputmode="decimal"` (no browser spinners, decimal keypad on phones). The page performs **no range validation**; the server's error is the validation.
- Resting value = last server-reported value (`temperature`, `humidity` in status). A field the user has edited ("dirty") keeps the user's text and shows a `#9aa1a9` 2px bottom border until committed or reverted. Incoming WS values never overwrite a focused or dirty field.

### 7. Message line (in the header, see cell table)

- Shows **only** the API's JSON error message, verbatim, for **5 s** *(default; D-17 says "a few seconds")*, then clears. A new error replaces the text and restarts the timer. Error text color `#ff4d4d`.
- If a response is not a JSON error (transport failure, proxy error), show `HTTP {status} {statusText}`; no invented prose.
- Idle: empty well.

## Interaction Contract

Every action maps to exactly one operation of the shared `/api/v1` vocabulary that the CLI also uses. The page contains no timing, no derived flags, no validation and no retry logic of its own (CLI-06, Anti-Pattern 3).

| UI action | Trigger | Operation (CLI equivalent) | After the call |
|-----------|---------|---------------------------|----------------|
| Change fan on port N | `change` on the select | `set portN.fan=<name>` (`sil set portN.fan=<name>`) | Applies immediately, **no confirmation** (D-16; instant unplug/replug per 02 D-10). On success the select shows the server-reported fan; the RPM axis re-scales once. On failure: message line shows the error, select reverts to the server value, red outline for 5 s. |
| USR hold start | `pointerdown` (primary button/touch), or `keydown` Space/Enter without `repeat` | `press usrN --down --max-hold <H>` | Cap does not change locally. It lights when the server reports the button held. |
| USR hold end | `pointerup`, `pointercancel`, `pointerleave`, `window blur`, `document visibilitychange` to hidden, `keyup` Space/Enter, element `blur` | `press usrN --up` | Sent only if this page started a hold that has not been released. Idempotent on the page side; the server rejects a redundant `--up` and that error is shown verbatim. |
| Set temperature/humidity | `Enter` in a field (that field only), or `APPLY VALUES` (all dirty fields in **one** `set`, all-or-nothing) | `set temperature=<v> humidity=<v>` | One call per commit, never per keystroke. On success the field returns to the server value and the dirty marker clears. On failure: message line shows the error, the offending field keeps the user's text and gets the red outline, which stays until the next edit of that field. |
| Revert edit | `Escape` in a dirty field | none | Field returns to the server value. |
| Initial load / reconnect | page load, WS reopen | status snapshot over WS, `history`, fan-library list | See "Connection and Stale State". |

Rules:
- **Max hold (D-15):** the page always sends a max-hold with `down`. Value: **10 s** of sim time *(default; well above the 1.5 s long-press preset)*. The engine auto-releases and reports it; the cap simply returns to released when the server says so. The safeguard lives in the API, not in JS.
- **No pointer capture:** do not call `setPointerCapture` on the caps; D-15 relies on `pointerleave` to release.
- **Server-driven state:** a rejected `down` (already held) shows the API's error in the message line and leaves the cap as the server reports it.
- **Disabled while stale:** when the WS is down, USR caps, fan selects, inputs and `APPLY VALUES` are disabled (`disabled` attribute plus 0.4 opacity). If a hold is active when the link drops, the server's max-hold releases it.
- **Fan-library list:** fetched once per (re)connect; the same list populates all four selects. If the call fails, each select shows only its current fan, disabled, and the error goes to the message line.
- No drag and drop, no right-click menus, no keyboard shortcuts beyond native control behaviour and Space/Enter on the USR caps. Tab order: header (none focusable) then P1 select, P2 select, P3, P4, USR1..3, Temperature, Humidity, APPLY VALUES.

## Connection and Stale State (D-10)

| State | LINK cell | Readouts / LEDs / plots | Controls |
|-------|-----------|-------------------------|----------|
| Connecting (first load, no snapshot yet) | `CONNECTING` | Readout values `--`, plots show the `WAITING FOR FIRST SAMPLE` empty copy, LED lenses off with captions `—` and `#------` | Disabled |
| Live | `LIVE` | Normal | Enabled |
| WS lost | `DISCONNECTED, RETRYING` (red) | Keep last values (no fake zeros), 0.4 opacity, LED lenses desaturated (`filter: grayscale(1)`) and 0.4 opacity, plot canvases 0.4 opacity and frozen | Disabled |
| Reconnected | `LIVE` | Fresh snapshot + history replace everything; plots repaint from history; opacity restored | Enabled |
| Firmware disconnected (WS fine) | `LIVE`; `FIRMWARE` = `DISCONNECTED` (red) | Server-reported values stay as reported; samples the server marks missing plot as gaps | Enabled |

- Reconnect backoff: 0.5 s, doubling to a 5 s cap, retrying forever *(default)*. No manual reload needed, including across `sil sim restart`.
- On reopen the page opens the WS first, buffers frames, fetches history, then merges by sim time `t` (drop duplicates), so no sample is shown twice or lost.
- "Stale" and "firmware disconnected" are different things and are never merged into one indicator.

| RPM, duty, scope | status/WS events, history | none | `sil status`, `sil watch`, history op |
| LEDs | status/WS events | none | `sil status`, `sil watch` |
| USR caps | status (held) | press down/up with `max_hold` | `sil press usrN --down --max-hold`, `--up` |
| Temp/humidity | status | set `temperature`, `humidity` | `sil set temperature=.. humidity=..` |

The check asserts: (a) every endpoint the page's JS calls is in the operation list, (b) the WS snapshot equals `GET status` for the same instant, (c) no `http(s)://` in the page's own served assets, and (d) the page loads and updates with all non-instance network access blocked.
