## Phase Goal

ROADMAP Goal (not in user-story form; surfaced for review, no story invented per the MVP rules): "The developer watches and drives a running bench from a local web page that is a pure client of the same API the CLI uses."

This plan is the phase tracer. It opens the one new front door (the instance's TCP listener) to the existing control handler, serves the embedded page shell and the /ws stream, and proves the path end to end against the real firmware. It advances success criterion 1 (page served from the binary, live over WebSocket) and carries the run-info data of criterion 4 in the /ws snapshot; 03-02 renders the readouts of criteria 2 and 4 and proves the page offline in a real browser.

<objective>
Serve a live page from `sil serve` on a sticky LAN web port: the existing control handler behind a redacting wrapper (D-18), a /ws adapter whose frames are `sil watch` lines, and an embedded vanilla-JS page shell whose store mirrors status from the snapshot and the typed events; then refuse the three lifecycle operations on the web listener (D-19).

Purpose: UI-01 (embedded page, no build step, no CDN, live over WebSocket), the run-info data of UI-05 in the snapshot; implements D-07 default bind, D-09 sticky port, D-10 reconnect core (in app.js; proven by 03-02), D-18, D-19.
Output: internal/web (web.go, ws.go), ui (embed.go, web/index.html, web/js/{app,store}.js), sticky web port in internal/instance, Status.Web, operation_not_allowed, e2e TestWebTracer.
</objective>
