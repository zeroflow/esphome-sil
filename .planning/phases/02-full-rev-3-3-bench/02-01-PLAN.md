## Phase Goal

ROADMAP Goal (not in user-story form; MVP framing needs `/gsd mvp-phase 2`, surfaced for morning review, no story invented): The complete Rev 3.3 IO surface runs in the sim and can be driven both from the CLI and from the user's own Home Assistant, with a contract test that proves the whole loop.

This plan is the phase tracer. It wires one path through every layer Phase 2 changes (new ESPHome platform, example firmware, engine World, supervisor operation, control API, CLI verb, e2e): `sil press usr1` reaches the real firmware as a button level, the firmware's own `on_click` logic changes the fan duty, and `sil status` shows it. Later plans widen the same path (LEDs, environment, fan choice, watch/logs, contract tests).

<objective>
Ship the button slice end to end: a `sim_bus` binary_sensor platform, the first version of `examples/rev33.yaml` (fans, RPM sensors, USR1-3 with the D-13 logic), button levels in the engine World with the released level in every in-snapshot, `Press` and raw `--down/--up` in the supervisor on the sim clock, `POST /api/v1/buttons/{id}/press|down|up`, `sil press`, `buttons` in `sil status`, and the full D-01..D-04 vocabulary with its error codes.

Purpose: IO-03 and the press half of CLI-02; proves the tracer architecture (component -> wire -> engine -> supervisor -> API -> CLI) for every later Phase 2 slice.
Output: binary_sensor platform, rev33.yaml, engine/supervisor/control/CLI press path, e2e TestPressTracer and TestPressVocabulary.
</objective>

3. Engine (button slice). ButtonIDs; the World holds a level per button, false at New.
