## Phase Goal

ROADMAP Goal (not in user-story form; surfaced for review, no story invented): "The developer watches and drives a running bench from a local web page that is a pure client of the same API the CLI uses."

This plan builds the spine of success criterion 5 ("an automated parity check confirms that every value the page displays and every action it performs is available through the CLI/API with the same JSON"): one operation table behind both listeners and the CLI, and the four parity checks. Later plans that add page operations extend the session list here.

<assumption_delta_decision>
`gsd-tools query assumption-delta scan 3 --json` returned `detected: false`. Recorded anyway because the phase adds a second listener next to api.sock: **promote**. The identity of the control API moves from "the api.sock socket" to "the control.Operations table"; api.sock and the TCP web listener are two transports with a policy each (socket: every row, full key; LAN: LAN rows only, api.key redacted, the rest refused). New operations are added as rows, and the listener policy follows from the row, never from a route registered elsewhere.
</assumption_delta_decision>

<objective>
Replace the inline route registration with a control.Operations table that registers the socket handler, builds the LAN handler (D-19 by row) and names the CLI command of every operation; then prove UI-06 with request parity, snapshot parity, displayed-value parity, page-state parity and the first-party asset scans.

Purpose: UI-06 checks a-d and the no-CDN half of UI-01; D-18 parity rule (api.key is the single socket/TCP difference), D-19 and D-20 as table rules.
Output: internal/control/operations.go, NewLANHandler, MatchOperation, TestOperationsCLI, TestSnapshotEqualsStatus, ui/ui_test.go scans, uitest/parity_test.go.
</objective>
