2. Hub (sim_bus.h/.cpp). Add the SimChild virtuals; in try_connect_ every chan frame uses child->type() and, when pixels() > 0, appends n and seg after type; add set_out_px mirroring set_out (first-write order in last_px_, unchanged content while connected sends nothing, otherwise store and send {k out, ch, px, t} and flush); the connect snapshot replays last_out_, then last_px_, then sync. Replay semantics (02-04 writes the same rule into the PROTOCOL.md "LED frames" paragraph): set_out_px stores the px also while the bus is down, so the replayed px is the strip state at reconnect (the newest px the light handed to the hub, changes made during the gap included), not necessarily the last px the previous connection received; both are equal only when the strip did not change in between. f32 chan frames keep exactly their Phase 1 bytes. The header stays platform-free.

3. Go wire and engine. bus.Channel gains N and Seg, read from the chan frame (`n` via GetInt, `seg` via GetStr); the growing struct breaks the unkeyed Channel literal in internal/bus/server_test.go (TestManifestAtSyncAndOutFramesInOrder), so rewrite it with keyed fields and add one case asserting that an rgb chan frame arrives as Channel{Ch leds, Dir out, Type rgb, N 5, Seg "board:0:0"}. Engine: `leds` is an optional channel (dir out, type rgb); on the manifest, N must be 1..255 and seg must parse as comma-separated `label:from:to` with label matching ^[a-z][a-z0-9_]*$, unique labels and 0 <= from <= to < N, giving segments label -> [from..to]; any violation is one warning naming the channel and the problem, and segments stay empty. An out frame on `leds` carrying px (accepted before the manifest too, because the firmware's px replay precedes its sync) must be an even run of hex digits, a multiple of 6 long and at most 1530 chars (6 x N once N is known); it is lower-cased and stored as strip entries "#rrggbb"; a bad px is one warning and keeps the previous strip; an out frame on `leds` with v but no px is a wrong-type warning. Before the first px of a session with a known N the strip is N x "#000000". Without a leds channel the strip is empty and segments empty, without a warning. publish copies strip and segments so Snapshot stays immutable. Supervisor Status maps snap.LEDs into control.LEDStatus with a non-nil slice and map.
