# API Coverage — ESPHome native API (firmware `api:` component, Noise-encrypted)

> Full coverage by default. Opt-outs are explicit, reasoned decisions.
> Scope: Phase 2 consumes the ESPHome native API in three places — the `sil serve` readiness probe (`internal/apiclient`, unchanged from Phase 1), the Go e2e client (`e2e/api_client.py` inside the pinned image) and the new pytest suite (`tests/silbench.py`, aioesphomeapi 46.12.0: TEST-02 smoke including the temperature/humidity arrival of criterion 5, and the HA-01/HA-02 proxies; the TEST-01 contract chain is `sil`-only and opens no API connection, per D-18). Home Assistant itself is a consumer of the firmware's API, never of `sil`; the simulator does not proxy the API. The `sil` control API (`/api/v1/*` on `api.sock`) is this project's own surface. Re-decided from the full-coverage baseline for the new pytest integration, not carried over from Phase 1.
