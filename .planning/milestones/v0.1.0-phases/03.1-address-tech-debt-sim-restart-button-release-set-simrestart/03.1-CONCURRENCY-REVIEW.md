# Phase 03.1: Independent re-review of the Set/SimRestart concurrency fixes

## Scope and method

Commits under review (all Phase 2, all in `internal/supervisor`):

- `e4f1046` fix(02): WR-02 keep the recorded Set state equal to the engine
- `da1a9ca` fix(02): WR-02 decide Set's dead-engine case on a real restart-gap flag
- `b976a6c` fix(02): IN-10 reset engGap with a defer so a SimRestart panic cannot leave it set
- `8542d9d` fix(02): WR-01 TestSupervisorRebootExit waits for the probe it asserts

`da1a9ca` and `b976a6c` were never re-reviewed after the Phase 2 iteration cap. Method: `git show` of the four diffs, the current `supervisor.go` (`run`, `startEngine`, `stopEngine`, `shutdown`, `stopAll`, `autoRestart`, `withDown`, `SimRestart`, `endEngGap`, `currentEngine`, `Set`) and `engine.go` (`Apply`, `handleApply`), then a failing test under `go test -race` for every claim that can be tested. Where this review differs, see "Disagreements".

## Concurrency invariants re-derived

Each item: verdict, then the code it rests on (`supervisor.go` unless stated; line numbers are the file after plan 03.1-02).

1. **Lock order `opMu -> inMu -> mu`.** Holds. Acquiring call sites:
   - `opMu`: `shutdown` (l.464), `autoRestart` (l.647), `SimRestart` (l.801), `FwRestart` (l.1283). `stopAll` is called with `opMu` held (or before any operation can run).
   - `inMu`: `run` (l.273, then `mu` inside at 279-281), `SimRestart` (l.828, released at 831/848/857, with `mu` taken inside it), `Set` (l.1201). `startEngine` takes none; its callers hold `inMu`.
   - `mu` only, never held while taking another lock: `Status`/`statusFrom`, `isStopping`, `currentEngine`, `endEngGap`, `stopAll`'s first section, `recordExit`, the probe setters.
   - `Press`/`SetButton` take no supervisor lock beyond `mu` via `currentEngine`.
   - Nothing takes `inMu` while holding `mu`, and nothing takes `opMu` while holding `inMu`. Verdict: holds.
2. **`engGap` lifecycle.** Holds. Set under `mu` at l.815 before `stopEngine(old)` (l.820), so a Set can only observe `ErrStopped` from the old engine after the flag is up. Cleared in one `mu` section together with the slot install (l.845-856), on a failed start (l.837), on an aborted gap sleep (`endEngGap`), and by the deferred `endEngGap` (l.819) on any other exit. A Set that read `engGap == true` holds `inMu`, which `SimRestart` also needs before `startEngine` (l.828), so a gap Set is always recorded before the next engine is seeded (`startEngine` copies `s.inputs`/`s.fans` at l.356-357). No lost update and no flag that outlives the restart.
3. **`Apply` on `withDown(context.WithoutCancel(ctx))` cannot hang a Set forever.** Holds. `Engine.Apply` returns on the reply, on `e.done` (engine stopped) or on its context (`engine.go` Apply, after the `e.done` pre-check). The context is cancelled by `withDown` when `downReq` closes. `stopEngine`/`stopAll` take no `inMu`, so a Set blocked inside `Apply` under `inMu` is released when the engine is cancelled. The only unbounded wait left is `inMu.Lock()` itself (F4).
4. **`engDied` is not raised for an engine SimRestart cancels.** Holds. `startEngine` sends on `engDied` only when `up.Load() && ctx.Err() == nil`; `stopEngine` cancels first (l.385-390).
5. **Record equals engine after quiescence.** Holds, and is pinned by `TestSetAndSimRestartKeepRecordAndEngineEqual` under `-race` (4 setters x 50 Sets against 20 SimRestarts, every Set answers nil, afterwards `Snapshot().Env == s.inputs` and every `Ports[i].Fan == s.fans[i].FanID`; 20 runs). A mutation that makes Set ignore `engGap` makes it fail with `engine_failed`, so it does bite. The argument it rests on: a Set that meets a stopped engine during a restart reads `engGap` true, because SimRestart needs `inMu` (held by that Set) to seed and install the next engine and clears the flag in the same `mu` section that installs it.
6. **WR-02 as amended.** While `inMu` is held, `s.inputs`/`s.fans` equal what the engine took, or what the next engine will be seeded with, or the call returned an error having rolled back. After this plan that holds on every return path of `Set`: parse errors and a gone caller return before anything is recorded; `ErrStopped` with a gap keeps the record by design; `ErrStopped` without a gap (dead engine, or a requested shutdown, F2), the shutdown-cancel arm (F6) and the unreachable `default:` arm all roll back.

## Disagreements

- **RESEARCH.md says F1 is "low severity (needs a dead engine)".** True of the rollback arms that existed in Phase 2, but F2 and F6 add two more rollback paths, so the unlocked read would have raced on shutdown paths too. Fixed once, in the rollback closure, so all of them are covered.
- **RESEARCH.md offers an `nPorts` field as an alternative F1 fix.** Not taken: element-wise `copy` makes the existing field comment ("its length never changes after Serve, only its elements, under inMu") true, with no second source of truth for the port count.
- **RESEARCH.md missed F6.** Its claim "the lock order, the `engGap` window and the rollback logic hold up" is right about the first two; the rollback logic still had the shutdown-cancel arm without a rollback. Found by checking each return path of `Set` against the WR-02 rule rather than the two arms the Phase 2 reviews discussed.
- **RESEARCH.md F5 says the `default:` rollback arm could be removed together with F2.** Not done (A-03.1-06): IN-08 stays outside this plan; the arm is harmless.
- **02-REVIEW.md IN-09 proposed `stopping || isDown(s.downReq)` with a rollback.** Taken as proposed; the rollback also went into the old `stopping` return, which previously left the record changed on that path. That is the same WR-02 rule as F6, found by the same path-by-path check.
- **02-REVIEW-DISPOSITION.md lists WR-02 as "fixed".** It was fixed for the paths named at the time; F1, F2 and F6 are the residuals, now closed.
- **No disagreement** on the `opMu -> inMu -> mu` order, the `engGap` lifecycle (set before the old engine is cancelled, cleared with the slot install, the `b976a6c` defer), `engDied` not firing for a cancelled engine, and `Apply` not hanging a Set. Each was re-derived above from the code.
