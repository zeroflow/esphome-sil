## Fixed Issues

### WR-02: `TestSimRestartReleasesAHeldButton` leaks the SimRestart goroutine and the replacement engine on any early failure

**Files modified:** `internal/supervisor/watch_test.go`
**Commit:** c717e8b
**Applied fix:** The cleanup is now registered immediately after the SimRestart goroutine starts, before any `t.Fatal` point. It closes `downReq` (aborting the gap sleep or resync wait), waits for the goroutine through a new `finished` channel (using `raceWait`, so a stuck SimRestart cannot hang the suite), then stops whatever engine is in the slot under `s.mu`. The old end-of-test cleanup was removed. The review's snippet read `<-errc`, which would block after the success path had already drained it, so a separate `finished` channel closed by the goroutine is used instead. A `t.Fatal` injected right after the goroutine start confirmed that the failure path returns promptly (no hang, no leaked goroutine); the injection was reverted.

### IN-04: README says the firmware sees the release "when it resyncs with the next simulator" for every stop cause

**Files modified:** `README.md`
**Commit:** 28dd601
**Applied fix:** Reworded the bullet after checking the code. A simulator restart keeps the firmware running, so it resyncs with the new simulator. `sil down` stops the whole instance, and an engine that dies on its own (`mainLoop`, `engDied`) ends the instance with `engine_failed` and the orderly shutdown stops the firmware group too, so in neither case is there a later resync. The review's suggested wording ("after a simulator restart ...") was extended to say this explicitly rather than implying the engine-failure case leaves a running firmware. The bullet now reads: the stream gets the release and `sil status` shows the button released; after a simulator restart the firmware sees the release when it resyncs with the new simulator; after `sil down` or an engine failure the whole instance stops, firmware included, so there is no later resync.

## Skipped Issues

### WR-01: Manual-clock tests wait for the gap sleep with `BlockUntil(1)`, which the old engine's ticker can satisfy

**File:** `internal/supervisor/watch_test.go:372-373` (also `internal/supervisor/supervisor_test.go:629`)
**Reason:** skipped: the premise does not hold in the current code. Both tests wait on `old.done`, which is `engineSlot.done`, not `Engine.done`. `startEngine` closes `sl.done` only after `eng.Run(ctx)` has returned (`supervisor.go:362-372`), and `Run` has run its `defer ticker.Stop()` by then. `manualTicker.Stop` removes the waiter synchronously under `Manual.mu`. So once `<-old.done` returns, the old ticker is no longer counted and `BlockUntil(1)` can only be satisfied by the gap sleep. The existing comment ("the old engine's ticker is gone with its done channel") is accurate for the slot's `done`. No change made (iteration 1; not revisited in iteration 2).
**Original issue:** `BlockUntil(1)` could return on the old engine's ticker before `SimRestart` arms its gap sleep, causing a latent flake.
