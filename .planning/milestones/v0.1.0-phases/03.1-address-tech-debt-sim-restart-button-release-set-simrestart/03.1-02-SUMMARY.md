# Phase 03.1 Plan 02: Set/SimRestart concurrency re-review Summary

**Independent re-review of the Phase 2 Set/SimRestart fixes (8542d9d, b976a6c, da1a9ca, e4f1046) found and fixed three real defects, each red under `-race` first: an `s.fans` slice-header data race between rolling-back Sets (F1), `engine_failed` instead of `stopping` in the shutdown window (F2, IN-09), and a shutdown-cancelled Set that kept its change (F6).**

## Performance

- **Duration:** 6 min (12:41Z to 12:47Z)
- **Tasks:** 2 (1 tracer, 1 TDD-style); 10 commits
- **Files modified:** 3 (review document, `supervisor.go`, `supervisor_test.go`)

## Accomplishments

- `03.1-CONCURRENCY-REVIEW.md` is a phase deliverable: a per-commit table of what each fix guards against and the invariant it sets up, the lock order `opMu -> inMu -> mu` with every acquiring call site, the `engGap` lifecycle, why `Apply` cannot hang a Set, findings F1-F7 each with status, evidence and disposition, and a Disagreements section against RESEARCH.md and the Phase 2 reviews. Frontmatter `status: complete`.
- F1 fixed: the rollback closure is `s.inputs = prevIn; copy(s.fans, prevFans)`, so the slice header is written only in `Serve` and the field comment is true.
- F2 fixed: in the `ErrStopped` no-gap branch, `stopping || isDown(s.downReq)` rolls back and answers `stopping`; `engine_failed` stays for a truly dead engine.
- F6 fixed: the `actx.Err() != nil` arm calls `rollback()` before `errStopping()`. Safe because a shutdown is terminal and seeds no later engine from the record.
- F4: Set's doc comment no longer claims it never waits for a restart.
- Stress test: 4 setters x 50 Sets against 20 SimRestarts, every Set answers nil and the record equals the engine afterwards. A mutation making Set ignore `engGap` makes it fail with `engine_failed`, so it bites.
